ROUTING - Proposed Project Structure

Goal: one installable package (routing). Every check can be called from UiPath, a pipeline, a notebook, or another project. Shared code lives in one place.

How the layers depend on each other

Imports only go downward. Nothing imports sideways (one check never imports another check).

What goes in each folder

foundation

core/

Small helpers that everything uses. Written once.

  • Plant, connection name
  • Snowflake + MSSQL connections
  • Material number cleaning (pad to 18 / strip zeros)
  • Excel read/write
queries

data/

Only SQL. Takes a list of materials, returns a DataFrame. When a query changes, you edit it here only.

  • Uses bound parameters, no f-string SQL
  • Batches large material lists
business logic

checks/

Each file has the same two functions:

  • check_xxx(df) -> df: pure and reusable
  • run(input_path, output_path=None): Excel wrapper
business logic

opc/

Builds the OpCenter submission Excel files. Uses core.db and data.tpm instead of its own connections.

orchestration

pipelines/

Chains checks together. pre_uipath = routing condition, then alt BOM, with one connection and one save. Returns exit code 0 (success) or 1 (error) for UiPath.

entry point

cli.py

One command for everything. Takes the file path as an argument (no input() prompt), so UiPath can run it unattended.

Old root scripts stay temporarily as 2-line shims, so existing UiPath / VBS calls keep working. Delete them once UiPath has switched over.

Rules

  1. One job per layer: queries in data/, logic in checks/ / opc/, file and argument handling in cli.py.
  2. No hardcoded values: plant and connection name in config.py, credentials in .env, file paths as arguments.
  3. Safe SQL: bound parameters, never string-built material lists.
  4. Verify by comparison: the new output must match the old script's output on the same input before an old file is removed.

Migration order

  1. pyproject.toml, core/, .gitignore cleanup
  2. routing_condition + alt_bom + pipelines/pre_uipath (your UiPath prerequisite), compared against old output
  3. Remaining checks, one at a time
  4. opc/ generators
  5. CLI, tests, README
